# Практическая работа №3 — «Панель администратора с динамическими дашбордами»

**Темы:** Razor-синтаксис, Layouts, ViewComponents
**Проект:** `DashboardAdmin` (ASP.NET Core MVC, .NET 8)

Создана страница админ-дашборда с карточками показателей, боковой панелью со сводкой
по трендам и многоуровневым layout. Выполнены все задания 1–6 и все три
дополнительных уровня (на «отлично»). Проект собирается без ошибок и предупреждений,
проверен в рантайне (запросы через `curl`).

---

## Задание 1. Модели и хранилище

- `Models/DashboardCard.cs` — модель карточки: `Id`, `Title`, `Value (decimal)`,
  `Trend (enum Up/Down/Stable)`, `Unit`, `Description`.
- `Services/IDashboardRepository.cs` — `GetAllCards()`, `GetById(int)`, `GetLatest(int)`.
- `Services/InMemoryDashboardRepository.cs` — статический список из **6 карточек** с
  разными трендами и единицами, одно значение отрицательное (Чистая прибыль −18500 руб.).
  Зарегистрирован в `Program.cs` как **Singleton**.

## Задание 2. Многоуровневый Layout

- `Views/Shared/_Layout.cshtml` — базовый: `<!DOCTYPE>`, `<title>@ViewData["Title"]`,
  шапка «Админ-панель» + навигация, подвал `© @DateTime.Now.Year Админ-панель`,
  `@RenderBody()`, секции `Scripts` (required:false), `PageHeader`, `Actions`.
  Условие: если `IsSectionDefined("PageHeader")` — выводится секция, иначе дефолтный
  заголовок «Панель управления».
- `Views/Shared/_AppLayout.cshtml` — дочерний, `Layout = "_Layout"`. Двухколоночная
  разметка: основная область + боковая панель с `@await Component.InvokeAsync("TrendSummary")`.
  **Проброс секций:** `_AppLayout` условно переопределяет `PageHeader/Actions/Scripts`,
  форвардя их из представления в `_Layout` (нюанс вложенных layout — секция «видна»
  только своему прямому layout).
- `_ViewStart.cshtml` — динамический выбор layout (см. средний уровень),
  `_ViewImports.cshtml` — `@using` моделей/сервисов проекта и `@addTagHelper`.

## Задание 3. Страница дашборда — Razor-логика (`Views/Dashboard/Index.cshtml`)

- `@functions` с методом `GetTrendLabel(Trend)` → «Рост / Снижение / Стабильно».
- Блок `@{ }` в начале: `totalValue` (сумма `Value`), `cardCount` (число карточек).
- `@section PageHeader` — заголовок «Дашборд» + подзаголовок
  «@cardCount показателей, сумма: @totalValue @ViewBag.Currency · период: @ViewData["ReportPeriod"]».
- `@foreach` по карточкам: заголовок, `@card.Value @card.Unit`, тренд через
  `@GetTrendLabel`, символ `↑/↓/→` по `Trend`, бейдж «Отрицательное значение» при
  `Value < 0`, описание.
- **Счётчик в цикле** `int i`: перенос строки каждые 3 карточки (`i > 0 && i % 3 == 0`),
  `i++` в конце.
- Сводка после цикла: «Всего карточек» и «Сумма значений».

## Задание 4. Partial-представление карточки

- `Views/Shared/_DashboardCard.cshtml` — **типизированная** модель `DashboardCard`,
  свой `@functions` с `GetTrendLabel` (ViewBag внутри partial не используется).
- В `Index.cshtml` часть карточек выводится **напрямую в цикле**, часть — через
  `@await Html.PartialAsync("_DashboardCard", card)` (показаны оба подхода).

## Задание 5. ViewComponent «Сводка по трендам»

- `ViewComponents/TrendSummaryViewComponent.cs` — получает `IDashboardRepository` через
  DI, группирует карточки по `Trend`, считает количество и сумму, возвращает `View(model)`.
- `Views/Shared/Components/TrendSummary/Default.cshtml` — заголовок «Сводка по трендам»,
  цикл по сводкам (название тренда, количество, сумма); если данных нет — «Нет данных».
- Вызывается в `_AppLayout.cshtml` в боковой панели.

## Задание 6. ViewData / ViewBag

- `DashboardController.Index()` передаёт список карточек типизированной моделью,
  `ViewData["ReportPeriod"] = "Сентябрь 2026"`, `ViewBag.Currency = "RUB"`.
- В `Index.cshtml`: `ReportPeriod` из ViewData и `Currency` из ViewBag выводятся в
  подзаголовке; над подзаголовком — Razor-комментарий `@* Данные за период из контроллера *@`.
- В начале страницы — HTML-комментарий `<!-- Админ-дашборд v1.0 -->`.

## Дополнительные задания (на «отлично»)

**Лёгкий — Razor-форматирование и условные бейджи.**
В `_DashboardCard.cshtml` добавлен метод `GetValueClass(decimal)` в `@functions`:
`< 0` → «Отрицательное», `0..<1000` → «Низкое», `1000..10000` → «Среднее», `> 10000` →
«Высокое». Результат вызова выводится рядом со значением карточки.

**Средний — динамический layout + секция с условным рендерингом.**
`_ViewStart.cshtml`: если `ViewData["Mode"] == "Print"` — `_PrintLayout`, иначе
`_AppLayout`. `_PrintLayout.cshtml` вкладывается в `_Layout`, без боковой панели
(только `@RenderBody()`); секции `PageHeader/Actions/Scripts` игнорируются через
`IgnoreSection`, чтобы Razor не ругался. `DashboardController.Print()` кладёт
`ViewData["Mode"] = "Print"` и возвращает тот же список. В `_Layout` добавлена секция
`@RenderSection("Actions", required:false)`; в `Index.cshtml` определён `@section Actions`
с кнопкой «Печать» (ссылка на `/Dashboard/Print`). Проверка `IsSectionDefined` в
`_Layout` не даёт упасть, когда секция не задана.

**Сложный — шаблонный делегат + комбинированная логика.**
В `Index.cshtml` объявлены два шаблонных делегата
`Func<DashboardCard, IHtmlContent> renderCard` и
`Func<IEnumerable<DashboardCard>, IHtmlContent> renderSummary` (неявный параметр `item`).
`renderCard` используется в цикле вместо partial; `renderSummary(Model)` выводит
количество, сумму и среднее (метод `GetAverage` из `@functions`). В комментарии Razor
объяснена разница делегата и partial.

## Ответы на вопросы работы

**Почему репозиторий Singleton?** Данные лежат в статическом списке в памяти. Singleton
даёт один общий экземпляр на всё приложение, поэтому список одинаков для всех запросов и
для ViewComponent. При перезапуске приложения данные (если бы они менялись) сбросились бы
к исходным — они не персистентны.

**Чем шаблонный делегат отличается от partial и когда что лучше?**
- *Partial* (`_DashboardCard.cshtml`) — отдельный `.cshtml`, компилируется как
  самостоятельное представление, переиспользуется между страницами, может иметь свою
  логику/`@functions`. Дороже по вызову.
- *Шаблонный делегат* — локальная inline-переменная `Func<T, IHtmlContent>` внутри одного
  представления: быстрый, виден только здесь, удобен для небольшого повторяющегося куска
  разметки в пределах страницы.

Итог: partial — когда разметку надо переиспользовать в разных местах проекта; делегат —
когда это локальный помощник рендеринга внутри одной страницы.
