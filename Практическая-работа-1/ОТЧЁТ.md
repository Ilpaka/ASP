## 3. Код формы и обработчика (шаги 3–4)

**Разметка (`Default.aspx`):**

```aspx
<asp:TextBox ID="txtName" runat="server" placeholder="Ваше имя" />
<asp:Button ID="btnOk" runat="server" Text="Поздороваться" OnClick="btnOk_Click" />
<asp:Label ID="lblResult" runat="server" />
```

**Обработчик (`Default.aspx.cs`):**

```csharp
protected void btnOk_Click(object sender, EventArgs e)
{
    lblResult.Text = "Привет, " + txtName.Text + "!";
}
```

**Результат (шаг 5):** при нажатии кнопки страница отправляет POST-запрос сама себе
(**постбек**), сервер заново прогоняет жизненный цикл, срабатывает `btnOk_Click`,
и в `Label` появляется приветствие «Привет, <имя>!». Введённое имя сохраняется в
поле ввода благодаря ViewState.

## 4. Порядок событий жизненного цикла с пояснением (шаг 6)

Обработчики `Page_Init`, `Page_Load`, `Page_PreRender`, `Page_Unload` дописывают
записи в `<asp:Literal ID="litLog">`.

**При первом заходе (GET):**

```
Init
Load
PreRender
```

**При постбеке (нажатии кнопки, POST):**

```
Init
Load
PreRender
```

Порядок одинаков, но **на постбеке между `Load` и `PreRender` дополнительно
срабатывают обработчики событий элементов управления** (например, `btnOk_Click`).
Это и есть суть событийной модели Web Forms: сервер полностью восстанавливает
состояние страницы из ViewState, затем вызывает обработчик того элемента, который
инициировал постбек.

Пояснение по этапам:
- **Init** — создаются элементы управления, ViewState ещё не применён.
- **Load** — состояние из ViewState уже восстановлено; здесь проверяем `IsPostBack`.
- **(обработка событий)** — только на постбеке: `btnOk_Click`, `btnCalc_Click` и т.д.
- **PreRender** — последний шанс изменить элементы перед формированием HTML.
- **Render** — генерация HTML (не переопределяли).
- **Unload** — очистка; вывести что-либо на экран уже нельзя, страница отдана клиенту.

## 5. Поле `__VIEWSTATE` и сравнение размеров (шаги 7–8)

`__VIEWSTATE` — скрытое поле формы (`<input type="hidden" name="__VIEWSTATE" ...>`),
в котором в Base64 сериализовано состояние серверных элементов управления. Оно
передаётся туда-обратно между браузером и сервером и восстанавливается на каждом постбеке.

| Состояние страницы                     | Размер `__VIEWSTATE` (символов) |
|----------------------------------------|---------------------------------|
| Без GridView (форма + Literal)         | `384`                 |
| С GridView на 3 строки (шаг 8)         | `1408`                  |

**Вывод:** добавление `GridView` с данными резко увеличивает размер `__VIEWSTATE`,
потому что в него сериализуется всё содержимое таблицы (тексты ячеек, структура).
Чем больше данных в элементах с включённым ViewState, тем тяжелее каждый запрос.
На реальных проектах для табличных данных ViewState часто отключают
(`EnableViewState="false"`), чтобы не раздувать трафик.

## 6. Продвинутый уровень (шаги 9–10)

**Шаг 9. Кнопка «Очистить».** Обработчик обнуляет `txtName.Text` и `lblResult.Text`.
После нажатия `__VIEWSTATE` меняется: очищенные значения элементов сериализуются
заново, поэтому строка `__VIEWSTATE` в HTML отличается от предыдущей.

**Шаг 10. Мини-калькулятор.** Два поля ввода, `DropDownList` с операциями
(`+ - * /`), кнопка «Вычислить», результат в `Label`. Деление на ноль
перехватывается через `try/catch (DivideByZeroException)` и выводит сообщение об
ошибке вместо падения страницы. Отдельно перехватывается `FormatException` для
некорректного ввода.

```csharp
try
{
    double a = double.Parse(txtA.Text);
    double b = double.Parse(txtB.Text);
    if (op == "/" && b == 0) throw new DivideByZeroException();
    // ... вычисление ...
}
catch (DivideByZeroException) { lblCalc.Text = "Ошибка: деление на ноль недопустимо"; }
catch (FormatException)       { lblCalc.Text = "Ошибка: введите корректные числа"; }
```

## 7. Вывод: что показал опыт и чем Web Forms отличается от MVC

Работа показала событийную модель Web Forms в действии: страница живёт по
жизненному циклу (`Init → Load → события → PreRender → Render → Unload`), а
состояние элементов между запросами держится в скрытом поле `__VIEWSTATE`.
Постбек — это отправка формы самой себе, при которой цикл выполняется заново, а
сервер восстанавливает состояние страницы и вызывает нужный обработчик.

**Отличия Web Forms от MVC:**

| Web Forms                                         | ASP.NET MVC                                        |
|---------------------------------------------------|----------------------------------------------------|
| Событийная модель, «как в desktop» (кнопки, события) | Модель запрос-ответ: маршрут → контроллер → представление |
| Состояние держится в ViewState (скрытое поле)     | Состояние не хранится автоматически; сервер stateless |
| Серверные элементы `<asp:...>`, постбеки           | Чистый HTML + помощники, обычные HTTP-запросы       |
| Быстрая разработка форм, но «тяжёлый» HTML/ViewState | Полный контроль над разметкой, лёгкий вывод, удобство тестирования |
| Абстрагирует HTTP от разработчика                  | Явная работа с HTTP, удобно для REST/AJAX/SPA       |

Главный практический вывод: удобство событийной модели Web Forms оплачивается
размером `__VIEWSTATE` и весом каждого запроса, тогда как MVC даёт лёгкую разметку
и явный контроль над HTTP ценой того, что состояние нужно вести самому.
