# Практическая работа «Безопасный Todo-менеджер»

Отдельный проект ASP.NET Core 8 по PDF «Практическая работа (8)». Второй файл, «Безопасность.pdf», использован как справочный материал. Реализованы все пять основных и три дополнительных задания.

## Запуск

Нужен .NET 8 SDK. Из папки `SecureTodo`:

```bash
dotnet restore
dotnet run
```

Откройте <http://localhost:5082/>. База SQLite `securetodo.db` создаётся при первом запуске. Swagger UI: <http://localhost:5082/swagger>. Примеры API-запросов находятся в [`SecureTodo/SecureTodo.http`](SecureTodo/SecureTodo.http).

В режиме Development создаётся администратор `admin@todo.com` с паролем `Admin123!`, как указано в задании. Он добавляется один раз. Для production задайте `Jwt__Key` (не менее 32 байт) и `SeedAdmin__Password` через переменные окружения; демонстрационный JWT-ключ из `appsettings.json` в production отклоняется.

## Реализовано

- Identity + SQLite: регистрация, вход, выход только POST, хеширование паролей, блокировка после пяти неверных попыток на 15 минут.
- Роли `Admin`, `Author`, `User`. Админ-панель показывает пользователей и роли; обычному пользователю отвечает 403. Роль User/Author меняется через POST-форму. Роль Admin нельзя снять с администратора. Обновление cookie с новыми ролями происходит при следующем запросе.
- Веб-список задач доступен после входа: обычный пользователь видит только свои задачи, администратор — все. Менять и удалять задачу может её автор или администратор. Проверка `CanEditTask` выполняется через `IAuthorizationService` после загрузки задачи и при каждом POST.
- API под JWT Bearer: вход, CRUD задач, список только собственных задач для обычного пользователя и всех задач для администратора. `UserId` при создании берётся из claims JWT. Swagger поддерживает Bearer-токен.
- Access JWT живёт 15 минут. Refresh-токен живёт 7 дней, хранится в SQLite, меняется при обновлении и отзывается при выходе или `logout-all`. `wwwroot/js/api-client.js` демонстрирует повтор запроса после обновления токена и переход на логин, если обновление не удалось.
- Настройка 2FA через ключ для приложения-аутентификатора и `otpauth://` ссылку, подтверждение шестизначным кодом, отдельный шаг при входе и отключение через профиль. API-вход также требует код, если 2FA активна.
- Глобальная проверка антифоргери-токенов для Razor Pages, токены в формах и `X-CSRF-TOKEN` для AJAX-кнопки «Отметить выполненной». Razor кодирует пользовательский текст; CSP запрещает инлайн-скрипты. Добавлены `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy` и HSTS.

Swagger UI использует встроенные inline-скрипты и стили, поэтому для маршрута `/swagger` у CSP есть отдельное послабление; страницы Todo остаются со строгим `script-src 'self'`.

## Проверка

Проект собран на .NET 8 без ошибок и предупреждений. Проверка с чистой базой подтвердила регистрацию и вывод полного имени, 403 для чужого редактирования и админ-панели, 401 без JWT, 400 без CSRF-токена, экранирование `<script>`, изоляцию задач двух пользователей, создание задачи с владельцем из JWT, refresh-ротацию и `logout-all`. Два одновременных запроса с одним refresh-токеном дали один успешный ответ и один 401. Проверены пять неверных паролей с блокировкой, повышение пользователя до Author с обновлением прав без перелогина и запрет понижения администратора. Проверен полный цикл 2FA: включение, дополнительный код при входе, отказ API без кода и отключение. Приложение использует строгий CSP, а Swagger UI открывается со своей отдельной политикой.

Проверочная база с временными пользователями удалена после проверки; при следующем запуске приложение создаст её заново.
