# Практическая работа «REST API для управления задачами (TaskFlow API)»

Отдельный проект `TaskFlowApi` по приложенному PDF. Реализованы уровни 1–3: CRUD, валидация и ProblemDetails, SQLite и миграция, DTO, комментарии, версии v1/v2, поиск и пагинация, идемпотентность POST, глобальный обработчик ошибок и CORS.

## Запуск

Нужен .NET 8 SDK и доступ к NuGet для первого восстановления пакетов.

```bash
cd TaskFlowApi
dotnet restore
dotnet run --urls http://localhost:5080
```

При старте автоматически применяется миграция `Init` и создаётся `taskflow.db`. Swagger UI: <http://localhost:5080/swagger>. Готовые HTTP-запросы находятся в `TaskFlowApi/TaskFlowApi.http`.

## Контракты

- `/api/projects`, `/api/tasks`, `/api/tasks/{id}/comments`, `/api/comments/{id}` — совместимые маршруты v1.
- `/api/v1/...` — контракт v1; помечен deprecated в описании версий.
- `/api/v2/tasks` — контракт v2. Ответ не содержит Description, но содержит Priority.
- `GET /api/v2/tasks` принимает `page`, `pageSize`, `status`, `priority`, `sortBy`, `sortDir`, `search`.
- `POST /api/v2/tasks` требует `X-Idempotency-Key` с GUID. Повтор с тем же телом возвращает сохранённые статус, JSON и Location; другой запрос с тем же ключом даёт 409.
- `PATCH /api/v2/tasks/{id}/status` не позволяет завершить задачу без комментариев: 422 ProblemDetails.

При первом старте создаются проект с ID 1, задача с ID 1 и пользователь `demo` с ID 1. Для добавления комментария используйте `authorId: 1`. Аутентификация в этом учебном задании не требуется; `PasswordHash` присутствует только в модели БД и никогда не входит в DTO.

## Хранение и ошибки

Миграция создаёт связи `Project → TaskItem → Comment` с каскадным удалением, индекс по статусу задачи, связь пользователя с задачами и комментариями и таблицу `IdempotencyRecords`. Исключения `NotFoundException` и `BusinessRuleException` преобразуются в 404 и 422; остальные исключения дают 500 без деталей реализации. CORS разрешает `http://localhost:3000`.

В PDF уровень 1 описывает временное хранение проектов в статическом списке, а уровень 2 заменяет его на EF Core. Поскольку реализован итоговый уровень 3, проекты сразу хранятся в SQLite.

## Проверка

Проект собран с .NET 8: 0 ошибок и 0 предупреждений. При запуске миграция создала SQLite базу с начальными записями. HTTP-проверки подтвердили Swagger, контракты v1/v2, пагинацию (400 при `pageSize=100`), 404 для отсутствующей задачи, правило 422, создание комментария и четыре сценария идемпотентности: отсутствующий ключ, первый запрос, повтор и конфликт. SDK для этой проверки был установлен во временный каталог; для самостоятельного запуска нужен установленный .NET 8 SDK.
