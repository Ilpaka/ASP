## Задание 1. AJAX-эндпоинты (`CatalogController`)

| Метод | Маршрут | Что отдаёт |
|---|---|---|
| `Search(string query)` | GET `/Catalog/Search?query=…` | HTML-фрагмент `_ProductList` (без layout) |
| `AddToCart(int id)` | POST `/Catalog/AddToCart` | JSON `{ success, cartCount, productName }` |
| `GetCartCount()` | GET `/Catalog/GetCartCount` | JSON `{ count }` |
| `LoadMore(int page)` | GET `/Catalog/LoadMore?page=2` | HTML-фрагмент следующей порции (пусто = конец) |
| `GetProductDetails(int id)` | GET | JSON с данными товара |
| `GetProductReviews(int id)` | GET | JSON со списком отзывов |

Корзина хранится в **сессии** (`builder.Services.AddSession()` + `app.UseSession()`),
как строка с ID через запятую — поэтому у каждого посетителя она своя.

## Ответы на контрольные вопросы

**Зачем `encodeURIComponent`?**
Он экранирует символы, недопустимые в строке запроса: пробелы, кириллицу, `&`, `#`, `+`.
Без него запрос `?query=чай & кофе` оборвался бы на `&`, и сервер получил бы только «чай».

**Почему `async/await`, а не `.then()`?**
`fetch` возвращает Promise. `await` позволяет писать асинхронный код в линейном виде,
как обычный последовательный, вместо вложенных `.then()`. Читается проще, а ошибки
ловятся обычным `try/catch`.

**Что будет без `try/catch`?**
При обрыве сети или ошибке сервера промис отклонится, исключение «утечёт» в
необработанный `unhandledrejection`, выполнение функции прервётся — и пользователь
навсегда останется со спиннером на экране, без объяснения что случилось.

**Почему `AddToCart` — POST, а не GET?**
Запрос **меняет состояние** на сервере (кладёт товар в корзину). GET по спецификации
должен быть безопасным и идемпотентным: его кэшируют браузеры и прокси, по нему
делают префетч. Товар мог бы «добавиться» сам при предзагрузке ссылки.

**Зачем `button.disabled = true`?**
Пока запрос летит, повторный клик отправил бы второй такой же POST и товар добавился
бы дважды. Блокировка кнопки — простейшая защита от двойной отправки, заодно
визуально показывает, что операция идёт.

**Что в `data.cartCount`?**
Актуальное количество товаров в корзине, **посчитанное сервером** после добавления.
Мы не увеличиваем счётчик на клиенте (`badge.textContent++`), потому что клиент может
рассинхронизироваться с сервером — источник правды один, и это сервер.

**Зачем запрашивать счётчик при загрузке страницы (`GetCartCount`)?**
Корзина живёт в сессии на сервере, а HTML-страница может прийти из кэша браузера
(кнопка «назад», повторный заход). Тогда в бейдже осталось бы старое число.
Отдельный запрос при `DOMContentLoaded` синхронизирует бейдж с реальным состоянием.

**Почему `site.js` подключается глобально, а `search.js` / `cart.js` — через секцию?**
`site.js` обновляет бейдж корзины, который есть в шапке **на каждой странице**.
А `search.js`, `cart.js`, `infinite.js`, `product-modal.js` работают с элементами,
которые существуют только в каталоге (`#searchInput`, `#catalogGrid`, `#sentinel`).
Грузить их на странице корзины — лишний трафик и разбор кода впустую. Секция
`@section Scripts` в `Index.cshtml` подключает их точечно.

## Дополнительные задания (на «отлично»)

**Лёгкий — Toast-уведомление.**
В `_Layout.cshtml` добавлена скрытая структура Bootstrap toast (`#cartToast`,
`#cartToastText`) в `position-fixed top-0 end-0`. В `cart.js` после успешного ответа
создаётся `new bootstrap.Toast(el, { delay: 3000 })` и вызывается `.show()` —
работа с JS-компонентом Bootstrap из своего кода.

**Средний — Бесконечная подгрузка (Infinite Scroll).**
`LoadMore(page)` отдаёт по 6 товаров. В разметке — пустой `#sentinel` в конце списка.
`infinite.js` через `IntersectionObserver` ловит момент, когда сентинель попал в зону
видимости (с запасом `rootMargin: 150px`), и догружает следующую порцию через
`insertAdjacentHTML('beforeend', html)` — это добавляет карточки, не перерисовывая уже
отрисованные. Флаг `isLoading` защищает от параллельных запросов, `hasMore` +
`observer.disconnect()` останавливают подгрузку, когда товары кончились.

**Сложный — Модалка с `Promise.all`.**
Клик по картинке или названию открывает модалку. `product-modal.js` сразу показывает
спиннер, затем **параллельно** запрашивает детали и отзывы через `Promise.all` —
это быстрее двух последовательных `await`. Детали обязательны (без них показывать
нечего), а отзывы обёрнуты во **вложенный** `try/catch`: если они не загрузились,
товар всё равно отображается, просто с надписью «Отзывов пока нет». HTML собирается
из JSON строками, весь текст с сервера прогоняется через экранирование.

## Что проверено в рантайне

- Сборка: 0 ошибок, бандлер собирает `site.min.js`, `catalog.min.js`, `site.min.css`.
- `Search` отдаёт фрагмент **без** layout (`<html>` в ответе отсутствует).
- `AddToCart` → `{"success":true,"cartCount":1,…}`; несуществующий товар и товар не в
  наличии → `{"success":false,…}` с сообщением.
- `GetCartCount` → `{"count":N}`, счётчик растёт по мере добавления.
- `LoadMore`: страницы 1–4 по 6 карточек, страница 5 — пусто (конец списка).
- Живой поиск в браузере: ввод «алгорит» → 2 карточки без перезагрузки.
- Добавление в корзину: toast «Товар «…» добавлен в корзину», кнопка зеленеет,
  бейдж в шапке меняется с 0 на 1.
- Модалка: детали + отзывы со звёздами, загруженные параллельно.
- Бесконечная подгрузка: 6 → 18 → 24 карточки, затем «Это все товары в каталоге».

## Замечания

- Оптимальнее оказалось **делегирование событий**: обработчики висят на `document`
  и ловят клик по всплытию. В методичке предлагается `querySelectorAll('.add-to-cart')`
  на загрузке, но тогда кнопки на карточках, пришедших из поиска и подгрузки, не
  работали бы — они появляются в DOM уже после подписки.
- Минификатор (NUglify) не понимает `catch {` без параметра (ES2019), поэтому в коде
  используется явное `catch (reviewsError)`.
- В `Program.cs` задана культура `ru-RU`: иначе `ToString("C0")` в контейнере выводит
  «¤» вместо «₽».
